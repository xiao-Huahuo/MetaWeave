# 2026-09-17

## 远程视觉模型与内置本地模型移除

- LLM 配置新增独立视觉模型名称、Base URL 与 API Key；三项全空时继承大模型，独立 Base URL 必须使用对应凭据。数据库通过 Alembic `20260917_0018` 增加可逆字段，并同步 REST、gRPC、OpenAPI 类型与前端设置。
- 新增统一远程视觉服务，将原图、先行 OCR 和用户问题以 OpenAI-compatible 多模态消息发送到当前视觉模型；会话图片自动识图与 `understand_image` 工具复用同一服务，并保留用户显式图片外发许可。
- 删除内置本地多模态模型的下载、加载、模型状态、主/小模型回退、模型管理卡片、存储路径、PyInstaller `torchvision` 绑定和运行时实现。无有效远程大模型时改为返回明确设置提示；旧版本遗留权重不会在升级中自动删除。
- 知识图谱改为远程小模型全文抽取并合并确定性显式关系规则；远程不可用时保留规则结果和已有图谱，同时提升 extractor/result 版本使旧本地模型缓存失效。
- 设置页增加视觉模型生效摘要、编辑、清空与预设导入，删除内置本地模型和 LLM“本地回退”文案；MinerU、PaddleOCR、Embedding 与 ReRank 流程保持不变。
- 兼容性影响：旧用户视觉字段默认为空并继承原大模型配置；如果继承的大模型不支持图片，应单独配置支持视觉输入的模型。移除内置本地模型不会单独解决 Embedding/ReRank 的跨平台 PyTorch 依赖问题。
- 全量刷新根 README、`docs/` 当前说明、旧版说明、兼容性审计、历史变更记录和验收快照，删除已失效的模型专名、测试记录与旧本地语言模型存储路径，统一采用当前远程视觉模型和受管本地检索/OCR 模型表述。
- Agent 文件工具统一为 `read_file`：知识库路径继续读取 Markdown 投影，`attachment://` 引用在首次读取时才复用 MinerU/本地解析与 OCR 流水线并缓存结果；`understand_image` 独立直接读取原图，不以前置 OCR 为条件。
- 会话附件上传改为只原子落盘和登记 `uploaded/unparsed` 状态，不再自动启动 OCR、文档解析或视觉调用。前端为每个文件独立发起请求，发送消息只等待并行网络上传取得正式引用，不等待任何解析；后端把同步文件与 SQLite 操作移入线程池，并以独占文件创建避免并行同名上传互相覆盖。
- 同步更新 Agent 工具注册表、工具选择说明、前端工具条名称/图标/结果摘要、观测指标、OpenAPI、内置工具清单、README 与工作流图；旧工具名仅在前端历史轨迹兼容映射中保留，不再对模型注册。
- 完成附件架构文档一致性审计：同步开发、架构、MCP、工具、动态上下文设计和验收清单，删除“上传后自动解析”“视觉必须等待 OCR”“附件已按块索引”等与当前实现不符的描述，并明确扫描器只是批量工作流。

## DeepSeek DSML 工具调用泄漏修复

- DSML 终态解析现在兼容分隔符与 `calls`、`invoke`、`parameter` 标签之间的空白，避免真实模型输出被误判为普通 assistant 正文。
- 流式过滤改为按 DSML 协议前缀识别，不再依赖少量无空格完整起始标记；协议文本不会在终态恢复前进入前端对话消息。
- 新增用户现场格式回归，覆盖 `search_knowledge`、`get_knowledge_file_status`、`get_knowledge_job_status`、多调用、布尔参数和单字符流式分片，并验证恢复后的消息继续路由到工具执行节点。

## 记忆工具权限与绑定一致性修复

- 长期记忆总开关成为记忆工具组的唯一权限源；旧 `disabled_tools` 中遗留的记忆工具名在读取和保存时自动规范化移除，开启长期记忆后整组工具真实绑定。
- `list_available_tools` 只返回当前用户实际启用的工具，并删除不存在的“下一轮自动放开绑定”说明。
- 模型决策节点把本轮实际绑定名单写入图状态，Action 节点在执行前进行最终授权校验；模型或提供商强行返回未声明函数名时只产生失败结果，不再执行副作用。
- Debug 工具注册表中的记忆工具开关改为由长期记忆总开关托管的只读状态，并补充后端、API 客户端、组件和 Chromium 界面回归。
- Agent 页左上角新增直连用户全局记忆配置的开关：审核与记忆文字始终使用全局文字色，审核状态点使用绿色/红色，记忆状态点使用主题色/红色；在 768px/480px 窄屏下压缩尺寸与隐藏标签。
