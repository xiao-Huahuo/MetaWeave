## 已废弃的本地模型回退与图片理解

- 新增 CPU 内置本地多模态模型共享推理服务：未配置大模型时同时承担主模型和小模型；仅配置大模型时小模型复用大模型；两者都配置时分别调用。该能力后来已被远程模型配置取代。
- 内置本地模型接入当时的模型下载、加载、状态、真实字节进度和存储路径管理，并扩展 REST、gRPC DTO 与前端类型。
- 修复内置本地模型下载在后端重启后长期停留于旧百分比的问题：从 Hugging Face `.incomplete` 断点文件恢复真实已下载字节，启动时自动续传，并避免磁盘检测覆盖活动下载状态。
- 修复模型管理页面仅在本页主动发起下载时才轮询的问题；页面首次读取到下载或加载状态时会自动开始刷新进度，任务结束后自动停止。
- 修复 Hugging Face 单分片权重采用分片文件名时被误判为模型缺失的问题；已下载权重可直接识别，无需重下。
- 修复内置本地模型加载所需运行时不完整及消息格式不兼容的问题：固定当时的 CPU PyTorch、Torchvision、Transformers 与 sentence-transformers 兼容组合，并让纯文本消息使用对应的多模态内容块格式；PyInstaller 不再排除 Torchvision。
- 修复检索记忆、压缩摘要或子 Agent 结果产生多个 system message 时内置本地模型拒绝生成的问题；本地适配器会保留并合并全部系统上下文，统一放到消息序列首位。
- 修复内置本地模型绑定工具后长时间停留在 Thinking、自然语言直到生成结束才出现的问题：本地适配器会按当前请求绑定至多一个相关工具，普通对话不再预填充 105 份无关工具 schema，并把面向云端模型的长系统上下文压缩为保留关键信息的首尾片段；普通回答立即流式输出，仅工具标记段保持缓冲；同时兼容当时的 XML 工具调用格式，并收紧 CPU 文本与识图生成上限。进一步修复 AVX2 Windows CPU 强制使用 BF16 软件模拟导致的极慢生成，改用该硬件实际高效的 FP32：矩阵基准中 BF16 比 FP32 慢约 297 倍；真实 HTTP/SSE 冷启动首片段由 19.24 秒降至 10.95 秒、完整回复由 33.28 秒降至 13.34 秒，模型已加载后的热请求首片段为 5.38 秒、完整回复为 7.65 秒。
- Agent 输入框右下角改为显示 `effective_model_name`；当时未配置远程大模型时会明确显示实际回退的内置本地模型，保存设置后也会立即刷新。
- LLM 配置页新增“当前生效”大小模型摘要，分别显示后端解析后的实际模型名，并区分本地回退、远程大模型复用和大小模型独立配置状态；未保存的编辑草稿不会冒充当前运行配置。
- 大模型和小模型配置分别增加复用存储管理删除样式的清空按钮；清空先进入编辑态、保存后生效，并移除小模型标题右侧的规则说明。
- 直接上传图片在 PaddleOCR 之后调用当时的内置本地视觉模型，合并文字与视觉语义到会话附件上下文；新增 Agent“识图”工具按需重新分析当前会话图片。
- 更新 README 与 `docs/WORKFLOW.md` 的模型路由、附件解析、识图工具及模型管理说明。
