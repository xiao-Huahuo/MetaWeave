# MetaWeave 图片与隐藏悬浮窗内存调查

日期：2026-10-03。仅进行测量；未修改应用源码、配置或原图。

## 用户要求与验收对应

- 调查图片开销：完成原图、长边不超过1600像素、1×1占位图三组对照，每组分别测有/无悬浮窗。
- 调查悬浮窗开销：记录独立悬浮窗渲染进程，并在同一实例冻结页面后销毁悬浮窗，比较前后采样。
- 如何减少图片开销：给出实测缩图收益和针对当前组件的加载优化建议；本轮不实施产品修改。

## 方法与范围

原运行环境已停止。本次在独立用户数据目录复制现有本地界面配置，连接项目真实Vite及Python服务，加载实际main.cjs、preload.cjs及Vue页面。两窗口组保持隐藏悬浮窗；单窗口组仅在临时加载副本中跳过悬浮窗启动和再次创建。原图不改，缩图/占位图只通过Playwright请求替换生效。所有组窗口1440×920逻辑像素，屏幕缩放125%，保持同一换图随机序列，六组实际请求的图片集合一致，均为30张。

主页有16个图片实例：两个轮播共10张幻灯片，同时挂载；其余6个导航块。每个实例加载原图计算亮度、每5秒概率换图。全量图库64张不是同时驻留的证据。

进入真实主页后等待20秒，再每3秒采样一次，共5次。以psutil memory_full_info().uss统计独占驻留物理内存，单位MiB，接近Windows任务管理器专用工作集，不是提交内存、总工作集或显存。不包含Python、Vite、PyCharm。截图确认原图和缩图主页正常呈现，全部组pageerror为空。

图片增量（原图减占位）：双窗口638.7 MiB，单窗口690.1 MiB。这是整个背景图加载/解码/缓存/合成路径的边际开销，无法精确拆成每张图片的驻留字节数。主要差异在GPU进程：双窗口634.8 MiB，单窗口673.6 MiB。

1600像素缩图节省：双窗口357.1 MiB（25.2%）；单窗口441.1 MiB（34.0%）。缩图后背景增量仍有双窗口281.6 MiB、单窗口249.0 MiB。

悬浮窗独立渲染进程约183–186 MiB。不同启动相减整组差值为121.2、205.2、172.6 MiB，受GPU和主页内存波动影响，不应直接当作严格的悬浮窗归因。

## 同一实例配对

补充实例：相同主页加载后通过CDP Page.setWebLifecycleState冻结两个页面以暂停换图/页面任务，5次1秒间隔采样；销毁悬浮窗，等待2秒，再5次1秒间隔采样。冻结前额外抽样集合31张，不能混入六组图片对照。

销毁前整组均值1398.6 MiB，销毁后1250.6 MiB，实测下降148.0 MiB。悬浮窗渲染自身约184 MiB；共享GPU缓存和主页进程仍波动，净下降小于渲染进程本身。不据此承诺所有运行阶段都固定节省148 MiB。

## 资源清单

64张原图文件合计40.0 MiB，完整RGBA解码理论总量1258.6 MiB；缩图后文件12.6 MiB、理论解码384.5 MiB。实际请求的30张原图理论解码563.4 MiB，缩图后176.9 MiB。仅为宽×高×4的量级估算，并非浏览器驻留实测。例：6016×4016照片92.2 MiB，1600×1068约6.5 MiB。

## 建议

1. 优先按显示用途生成缩图，保留原图。大轮播可先验证1600像素档，小卡片用640/960像素档；按容器大小、devicePixelRatio及cover裁切比例选择档位，为高分辨率/最大化窗口保留更大档。保持透明通道、EXIF方向和原构图。1600是本次测量档位，不是所有屏幕的固定最佳值。
2. 轮播仅加载当前和相邻幻灯片的背景，其余保留同尺寸容器，避免屏幕外全部解码；保留既有轮播入口与动画功能。
3. 屏幕外幻灯片、隐藏窗口和隐藏主页暂停随机背景替换，在显示前恢复/预载下一张，减少不断进入缓存的新图片。
4. 亮度计算使用同一缩图响应；32×32采样canvas不能阻止new Image()先读取原图。
5. WebP/AVIF或降低JPEG质量主要减少文件和下载体积；相同像素尺寸通常仍需同量级像素内存，不能代替缩尺寸。
6. 悬浮窗如后续优化，可保持同一组件复用，按首次显示创建，并评估AgentPanel的延迟导入。当前实际代码选择常驻/隐藏，隐藏不会释放其渲染进程。

生产构建、实际主页显示和轮播切换均通过，pageerror与图片失败列表为空；截图经过视觉检查。证据：home-image-migration.json、home-image-smoke.json、home-thumbnails.png、home-thumbnails-carousel.png。未修改轮播组件、悬浮窗生命周期或加载策略；仅本轮已授权的资源处理。


## 后续实施：悬浮窗首次使用时创建

用户要求“首次使用时再创建窗口”：启动回调不再调用 `createFloatingWindow()`；真实界面启动只出现主窗口。

“只有用户设置里面启用小窗的时候以及其重新开启之后，再创建这个小窗”：设置恢复/启用的 `floating:set-visible(true)` 和托盘原生菜单仍按需调用现有创建函数；禁用首次请求不创建，窗口已存在时重开复用、已销毁时重建。设置用户持久化/API合同未改，验证调用设置页同一真实桌面桥，不改用户设置。

“否则完全没必要随着主窗口一起创建”：修改前确认启动创建隐藏悬浮窗，修改后等待主界面完成用户设置恢复，仍只有主窗口；没有悬浮窗渲染进程。

逐项真实窗口状态见 floating-lazy-startup.json，截图 floating-lazy-open.png。九个状态检查与页面错误检查通过。关闭/禁用仍隐藏而非销毁，避免本轮扩大到流式对话所有权迁移；未调整完整AgentPanel挂载或窗口交互。共同入口静态核对开发/发布路径，未重新生成安装包。
