## 复现及修复

- 真实旧 SDK readonly 调用 write 被沙盒拒绝，目标文件不存在，但 schema 显示 read/write/edit/read_image；问题是工具暴露和能力声明不准确。
- SDK `session/open` 返回真实 scoped tools 并声明 mw-tools-v1；只读工具隐藏 write/edit，仍保留底层拒写保护。任务合同和实际权限说明传递给 DSH。
- 后台启动在握手前工具目录为空；能力事件通过正式会话/消息持久化，任务结果使用实际工具名称。completed 表示本轮结束，父 agent 必须逐项核对完成情况。
- 点击 DSH 不再调用外部浏览器。受管 DSH 使用内存 Chromium session、关闭缓存、直连本机；普通浏览保留原会话。认证 URL 在原生视图内保留，地址栏和错误信息脱敏。
- DSH Web 输入控件真正 disabled/readOnly，动态控件受 MutationObserver 保护；搜索、导航、复制保留，HTTP 网关继续拒绝写动作。
- 实际 Windows 安装出现 staging 重命名 WinError 5：只对 WinError 5/32 做有界、可取消的重试，永久失败仍清理 staging 并返回失败。服务默认 `install_finalize_timeout_seconds=5.0`、`filesystem_retry_delay_seconds=0.1`，由 AgentConfig 及对应环境变量统一管理。
- 全新评测资料库未初始化 Embedding 时，原 SSE 生产线程会因上下文异常退出而不给界面错误/结束事件。现在早期及中途异常均发送安全的 error 节点并结束流，源迭代器在生产线程关闭；未放宽模型就绪要求。

## SDK 固定名称与垃圾清理

用户后续要求直接替换旧 SDK、统一叫 sdk、清理垃圾并同步 README。现资源包和 manifest 使用固定文件名，安装目录固定为 `runtime/assets/sdks/dsh/sdk`；兼容修订号只保留在校验元数据，不按版本目录并存 SDK。源码补丁与 ZIP 内容没有改变，更名仅调整 manifest 的 archive_file，ZIP 哈希保持一致。

正式安装流程成功后清除旧 versions 及已知 .sdk-* 残留，校验/取消失败保留旧缓存，活动租约拒绝替换；清理失败明确 failed，不宣称 ready。实际先通过 Vite/正式 REST 卸载当前闲置旧 SDK，再用正式 manager 校验、解压、自检并安装固定 sdk。旧 SDK、当前版本目录和失败 staging 的旧布局共约 530 MB，现只保留约 192 MB 的单一安装。
